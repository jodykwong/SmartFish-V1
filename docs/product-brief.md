# Product Brief: SmartFish 分析方法论增强

## 问题陈述

### 当前痛点
用户使用 BettaFish 生成的报告存在以下问题：
1. **内容与需求不对齐** - 用户要求分析 5 个方向，系统只输出 2 个
2. **缺少结论章节** - 报告有大量数据但没有可行动的建议
3. **Agent 偷懒** - 直接使用 prompt 中的示例，不执行真正的搜索

### 根本原因
- 系统是**模板驱动**而非**需求驱动**
- 章节生成 prompt 强调"按模板生成"而非"满足用户具体要求"
- 缺少需求-输出对齐验证环节

## 目标用户

| 用户类型 | 核心需求 |
|---------|---------|
| 产品经理 | 快速验证产品方向，获得有数据支撑的建议 |
| 创业者 | 发现市场机会，了解竞品弱点 |
| 市场分析师 | 深度行业洞察，趋势预测 |

## 核心价值主张

**将 BMAD 的结构化分析方法论注入 BettaFish 的数据引擎**

- BettaFish = 数据采集能力（眼睛）
- BMAD 方法论 = 分析框架（大脑）
- SmartFish = 有方法论指导的数据洞察

## 功能需求

### P0 - 必须有

1. **需求对齐验证**
   - 报告生成后自动检查是否满足用户具体要求
   - 检查项：数量要求、格式要求、结论章节

2. **结论章节强制生成**
   - 所有报告模板必须包含"结论与建议"章节
   - 每个结论必须有数据来源引用

3. **防偷懒机制**
   - 检测 Agent 是否直接复制 prompt 示例
   - 强制要求搜索结果作为内容来源

### P1 - 应该有

4. **分析方法选择器（Web 端）**
   - 用户可选择分析方法：六顶思考帽、五个为什么、SCAMPER 等
   - 选中的方法注入到 Agent prompt

5. **分析模式切换**
   - 舆情监控模式（默认）
   - 产品洞察模式
   - 竞品分析模式

### P2 - 可以有

6. **假设验证清单**
   - 标记无数据支撑的结论为"待验证假设"
   - 生成验证实验建议

## 成功指标

| 指标 | 当前 | 目标 |
|-----|------|------|
| 需求满足率 | ~40% | >90% |
| 报告含结论章节 | 0% | 100% |
| 用户满意度 | - | >4/5 |

## 约束条件

- 不改变 BettaFish 核心爬虫能力
- 通过配置文件实现，避免硬编码
- 保持与现有报告模板兼容

## 里程碑

| 阶段 | 交付物 | 时间 |
|-----|-------|------|
| M1 | 需求对齐验证 + 结论章节强制 | 1 周 |
| M2 | 分析方法选择器 | 2 周 |
| M3 | 分析模式切换 | 3 周 |
