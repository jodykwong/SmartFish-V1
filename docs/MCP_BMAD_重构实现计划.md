## 一、背景

### Part 1: 混合采集架构 (Hybrid Data Acquisition)
经过技术评估，我们决定采用 **"MCP + MediaCrawler"** 的混合架构来平衡开发效率与数据质量：
1.  **MCP 优先 (Quick Win)**: 针对维护活跃的 MCP 项目（微博、抖音），优先通过 MCP 快速接入。
2.  **MediaCrawler 兜底 (Deep Dive)**: 针对 MCP 维护停滞的平台（知乎、B站），集成 MediaCrawler (40k+ Star 强力爬虫) 作为核心采集能力。

### Part 2: BMAD验证方法论
根据YC "How To Get Your First Users" 和 Zero to Sold 理论：
- 获取早期用户是"搜索问题"而非"说服问题"
- 互联网数据是被动数据，无法做主动调查
- 应从被动数据中挖掘付费意愿、绝望程度等信号

## 三、关键决策更新

| 问题 | 原计划 | **当前新决策 (v2.1)** |
|------|--------|----------------------|
| **微博/抖音** | 使用 MCP | **✅ 继续使用 MCP** (官方/活跃维护，配置简单) |
| **知乎/B站** | 使用 MCP | **🛑 切换至 MediaCrawler** (原MCP已废弃，改用强力爬虫) |
| **数据一致性** | 统一定义 | 通过 **DataSourceRouter** 统一不同来源的数据格式 |

## 四、实施计划

### Phase 1: 激活 MCP 核心 (微博/抖音) - [进行中]
目标：低成本快速打通两个高价值平台。
1.  **[配置]**: 安装 `mcp-server-weibo` 和 `douyin-mcp-server`。
2.  **[认证]**: 配置微博 Cookie 和阿里云 API Key。
3.  **[测试]**: 验证微博热搜和抖音视频解析功能。

### Phase 2: 集成 MediaCrawler (知乎/B站) - [待启动]
目标：攻克高难度平台，获取深度内容。
1.  **[集成]**: 将 MediaCrawler 核心代码更新到项目 `MindSpider/` 目录。
2.  **[适配]**: 编写 Python 适配器，使其通过 CLI 或 API 方式被 SmartFish 调用。
3.  **[统一]**: 确保其输出数据格式与 MCP 返回格式一致 (`MCPSearchResult`)。
